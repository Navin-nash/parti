Component

The rack, in every state a shift produces

One component carries almost the whole product, so it is specified in full here rather than left to whoever builds the next screen. The rule underneath every state below: a dispatcher must never be able to mistake absent data for good data.

Bay

Physical rack bay the strip would sit in. Carried over from the paper rack so a dispatcher who trained on strips reads it without being told.

Flight

Carrier flight number. Highest weight in the row after the state token — it is what gets said out loud on the phone.

Tail / Type

Registration and ICAO type. Never truncated, never abbreviated: a wrong tail is an airworthiness event.

Route

IATA origin and destination, tracked wider so the pair reads as one object.

STD / ETD

Scheduled and estimated departure, Zulu, tabular figures, right-aligned so the column scans vertically.

Delta

Signed difference, amber past 15 minutes, red past 60. Never shown as a bare number without its sign.

Crew

Captain and first officer surnames, uppercase, as they appear on the release.

Duty left

Time to the crew's hard FAR 117 limit. Amber under 2:00, red at zero.

Load

Booked over capacity. Two numbers, not a percentage — a dispatcher rebooking needs the count.

State

The printed status token. Redundant with the row tint and the delta colour, so the row still reads in grayscale or in peripheral vision.

State 1

Populated

The working state. Tint, token and delta colour all move together, so no single channel is load-bearing. Rows never truncate; the rack scrolls sideways instead, because a clipped tail number is worse than a scrollbar.

State 2

Empty

An empty rack is ambiguous — it can mean a quiet hour or a filter that excluded everything — so it always says which, restates the filter that produced it, and offers the single widest action rather than a shrug.

0 legs · filter: bay C · irregular only · 1400Z–1800Z updated 3s ago
Rack · empty
BayBAY Flight Tail Type Route STD ETD Delta Crew Duty left Load State

Nothing irregular in bay C this window.

Bay C has four scheduled legs between 1400Z and 1800Z and all four are running to plan. The rack is empty because of the filter, not because the feed is quiet — the ribbon above still reads three seconds.

State 3

Loading

The rack and its field rules are drawn immediately; only the values are pending, shown as unfilled fields that pulse in place. Nothing reflows when the data arrives, because the geometry never depended on it. No spinner: a dispatcher needs to know which fields are missing, not that something is happening.

BayBAY Flight Tail Type Route STD ETD Delta Crew Duty left Load State

Announced to assistive technology as “Rack loading, outbound PDX” via the busy region above; the row count is announced once when it resolves, not on every field.

State 4

Error

The one state that gets the warning fill. Meridian will not show a rack it cannot vouch for, so the last-known data is withdrawn rather than left on screen looking current, and the desk is moved to manual entry in the same breath.

Feed lost · ARINC primary and secondary last good frame 1419:44Z 2m 23s stale
Rack · error
BayBAY Flight Tail Type Route STD ETD Delta Crew Duty left Load State
Feed lost

The rack is stale and has been withdrawn.

Both ARINC connections dropped at 1419:44Z. The 47 legs last received are held but not displayed, because an ETD that is two minutes old looks identical to one that is current and there is no safe way to tell them apart on a strip. Manual entry is open on all fields and anything you type is queued for reconciliation when the feed returns.

Retrying automatically every 15 seconds. Attempt 10 of unlimited.
